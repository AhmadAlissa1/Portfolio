Malaysia LHDN e-Invoice Integration

A production-grade NetSuite ↔ LHDN (IRBM) integration that automates the submission, validation, and cancellation of e-invoices, credit notes, debit notes, and refunds — with near real-time feedback and a clean audit trail.

Financial Compliance 2024 Malaysian enterprise NetSuite customer
Explore more case studies Discuss a similar project

Business Problem

Malaysia's LHDN e-Invoice mandate requires validated, real-time invoice submission from ERP systems. NetSuite has no native integration, leaving finance teams to export, reformat, and re-key documents into the MyInvois portal — a process that does not scale, breaks reconciliation, and exposes the business to compliance risk.

Solution

A SuiteScript 2.x integration that intercepts the invoice lifecycle in NetSuite, maps fields to the LHDN UBL schema, signs requests with the taxpayer's client credentials, and persists LHDN validation responses and reference numbers back on the source transaction. A scheduled retry handles transient failures, and a dedicated API covers the supported cancellation flow.

Architecture

  1. 1NetSuite — UserEvent & Scheduled scripts trigger on Invoice / Credit Memo / Customer Refund / Debit Note
  2. 2Integration layer — SuiteScript modules map NetSuite records to LHDN UBL 1.1 documents, applying per-supplier and per-tax-type rules
  3. 3Identity & transport — OAuth2 client-credentials flow with NTLM-protected REST calls; tokens cached in a NetSuite credential record
  4. 4Response handling — Validation status, UUID, and long ID are written back to the source transaction and surfaced in a custom portlet
  5. 5Resilience — Scheduled retry queue, idempotency keys, and a reconciliation saved search for daily LHDN status checks

Process Flow

Start
Document Creation
Invoice / CM / Refund / Debit Note
Data Transformation
Map to LHDN UBL 1.1 schema
LHDN Submission
OAuth2 REST call, idempotency key
Response Handling
Status, UUID, long ID written back
User Notification
Inline status on the record
Document Finalization
LHDN reference stored for audit

Technical Challenges

  • Reconciling NetSuite's multi-subsidiary tax engine with LHDN's TIN/MSIC validation rules
  • Handling network and certification-sandbox outages without blocking finance users
  • Designing a mapping that survives schema changes from LHDN with a single config deploy
  • Maintaining idempotency so duplicate submissions cannot occur during retries

Key Features

  • Automatic submission of invoices, credit memos, debit notes, and refunds
  • Near real-time validation status with LHDN reference number stored on the record
  • Cancellation API with full audit trail and reason codes
  • On-demand status, notification, and supplier-inquiry APIs
  • Custom record to track every submission, response, and retry for the audit team

Outcome

  • Replaced a manual portal-driven workflow with a fully automated submission pipeline
  • Validation feedback is visible to finance within seconds, not the next business day
  • Zero duplicate submissions during a 6-month production run (idempotency keys verified)
  • Audit-ready history of every document submitted, validated, or cancelled

Banking & Treasury 2023

Multi-Bank EFT Customization

Custom EFT templates and a SuiteScript payment-file generator that produce compliant XML and TXT files for Mizuho, MUFG, SMBC, HSBC, DBS, AmBank, ADIB, DuitNow, and JomPAY — without leaving NetSuite.

Business Problem

Each bank enforces a distinct EFT schema (XML or TXT) with strict field-level rules. The client's AP team was hand-editing exported files in Excel for every batch — slow, error-prone, and a recurring audit finding.

Solution

Bank-specific FreeMarker templates hosted alongside NetSuite, a SuiteScript 2.x record that holds payment instructions, and a scheduled script that renders the appropriate template, validates totals and IBAN/BIC, and produces a downloadable payment file ready for the bank portal or SFTP drop.

Architecture

  1. 1FreeMarker templates (.ftl) stored in the File Cabinet, one per bank and per format (XML / TXT)
  2. 2SuiteScript 2.x payment-run record captures vendor, bank, amount, and value-date
  3. 3Template engine (BFO FreeMarker / Freemarker.js) merges data into the bank's expected layout
  4. 4Validator runs pre-flight checks: IBAN, BIC, duplicate references, daily cut-off, and totals
  5. 5Output file is saved to the File Cabinet and surfaced as a download link on the payment run

Process Flow

Start
Vendor Bill Selection
AP picks approved bills for a payment run
Payment Run Record
Bank, format, value-date captured
Pre-Flight Validation
IBAN, BIC, totals, cut-off, duplicates
FreeMarker Render
Bank-specific XML / TXT generated
File Cabinet + SFTP
Versioned output, ready for bank portal

Supported Banks & Schemes

DBSMaybankMUFGSMBCCIMBAmBankUOBADIBDuitNowJomPAY

Technical Challenges

  • Normalising nine bank schemas into a single data model without leaking bank-specific fields
  • Producing files that pass strict character-set and decimal-place checks on first run
  • Auditing every generated file against the originating vendor bill at any point in time

Key Features

  • Bank-specific templates for Mizuho, MUFG, SMBC, HSBC, DBS, AmBank, ADIB, DuitNow, JomPAY
  • XML and TXT output formats driven by the same data record
  • Pre-flight validation with line-level error reporting
  • Re-runnable payment runs with versioned output files
  • Full audit trail from vendor bill to generated payment file

Outcome

  • AP batch close-time cut from 2 days to under an hour
  • Eliminated manual Excel editing of payment files
  • Onboarding a new bank now requires only a new FreeMarker template, not new code

Inventory & Distribution 2023

Serial Number Customization with FIFO Selection

Bulk import of up to 8,000 serial numbers per Item Receipt and an automated FIFO engine that picks the oldest available serials for every Delivery Order — fully auditable across channels.

Business Problem

NetSuite's native serial-number flow required serials to be entered one-by-one during receipt, and the team had no consistent method for assigning the oldest serials to outgoing shipments. Aged inventory accumulated, and the audit team lacked a unified transaction history.

Solution

A SuiteScript-driven bulk intake screen for Item Receipts, a custom serial ledger that tracks every movement with timestamp and source transaction, and a beforeSubmit hook on Delivery Orders that resolves the oldest available serials for each line — without re-inventing NetSuite's native engine.

Architecture

  1. 1Custom Record — Serial Ledger stores every serial with receipt date, location, and current status
  2. 2Suitelet — Bulk serial intake supports up to 8,000 numbers per Item Receipt via paste / CSV
  3. 3UserEvent script — beforeSubmit on Delivery Order allocates the oldest available serials FIFO
  4. 4Search-driven UI — A saved search exposes full transaction history per serial across channels

Process Flow

Start
Item Receipt
Bulk import up to 8,000 serials
Serial Ledger
Persist with timestamp & location
Delivery Order
FIFO beforeSubmit hook
Oldest serials allocated first

Technical Challenges

  • Meeting NetSuite governance limits when validating 8,000 serials in a single request
  • Preventing race conditions when two users allocate from the same lot at the same time
  • Keeping the custom ledger consistent with native NetSuite inventory movements

Key Features

  • Bulk serial import for Item Receipts (up to 8,000 per transaction)
  • FIFO-based automatic serial selection on Delivery Orders
  • Unified serial transaction history across sales channels
  • Aged-inventory and channel-movement analytics from the same data set

Outcome

  • Receipt processing time reduced from days to minutes
  • FIFO enforcement is automatic — no more aged-stock write-offs
  • Audit team has a single source of truth for every serial's history

Manufacturing & Service 2023

Disassembly Item Workflow

A structured disassembly record that captures serialized and non-serialized components, then automatically posts the inventory adjustment — replacing a manual, error-prone spreadsheet.

Business Problem

When a complete unit (for example, a desktop PC) had to be broken down for parts or warranty recovery, the operations team recorded the components in a spreadsheet and keyed the inventory adjustment by hand. Stock accuracy suffered and components were routinely lost.

Solution

A custom Disassembly record that links a main serialized item to its components, captures quantity, rate, and serial number where applicable, and a UserEvent script that posts the matching inventory adjustment on submit, keeping the main item and its components in lock-step.

Architecture

  1. 1Custom Record — Disassembly with main item, component sublist, and rate fields
  2. 2UserEvent script — beforeSubmit validates components, afterSubmit posts the inventory adjustment
  3. 3Validation — Serialised components require a serial; non-serialised items require a rate

  • Reversing a disassembly cleanly when an operator makes an error

Key Features

  • Single-screen disassembly capture with component sublist
  • Automatic inventory adjustment on submission
  • Support for both serialised and non-serialised components
  • Full traceability from main item to individual components

Outcome

  • Stock accuracy on disassembled SKUs improved to 100% in the first quarter
  • Recovery time for components reduced from hours to minutes

Pricing & Audit 2023

Item Price Log Change

An always-on audit log that records every change to an item's price — who, when, old value, new value — without altering NetSuite's live price behaviour.

Business Problem

The pricing team needed a tamper-evident history of every price change for audit and strategy reviews, but the existing record of changes in NetSuite was incomplete and not easy to export.

Solution

A UserEvent script that hooks into item save, writes a Price Log record capturing timestamp, user, old price, and new price, and a saved search that exposes the history with CSV export.

Architecture

  1. 1UserEvent script — beforeSubmit compares old and new price and writes a Price Log record
  2. 2Custom Record — Price Log captures item, user, timestamp, old price, new price
  3. 3Saved search — exposes the log to finance with export to CSV

Quality Control 2023

Warranty Check on Invoice

A real-time serial-number uniqueness check on invoice save that prevents duplicate warranty registrations and surfaces the existing record to the user for a confident decision.

Business Problem

Service agents could accidentally invoice a serial that was already registered for warranty, leading to duplicate claims and customer disputes.

Solution

A UserEvent validation on Invoice that checks each serial against the warranty register, blocks the save with a clear error referencing the original invoice, and offers a replace / cancel decision path for the agent.

Architecture

  1. 1UserEvent script — beforeSubmit validates each serial against the warranty register
  2. 2Custom sublist — surfaces the conflicting invoice and customer details
  3. 3Decision UI — replace serial, keep the existing registration, or cancel the invoice

  • Validating large invoices without exceeding governance limits
  • Surfacing enough context for the agent to make the right call without leaving the screen

Key Features

  • Real-time duplicate-serial detection on invoice save
  • Inline alert showing the original invoice and customer
  • Replace / cancel decision flow directly on the form

Outcome
